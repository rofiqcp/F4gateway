BUILD FIX 2026-09-03

Problem fixed:
PlatformIO/TFT_eSPI 2.5.43 reported redefinition errors for FreeSans9pt7b,
FreeSansBold9pt7b, FreeSansBold12pt7b, FreeSansBold18pt7b and
FreeSansBold24pt7b.

Root cause:
platformio.ini enables -DLOAD_GFXFF. TFT_eSPI.h then includes
Fonts/GFXFF/gfxfont.h, and gfxfont.h already includes the complete GFX FreeFont
set. Theme.h was including several of the same font headers a second time.
Those font header files do not have independent include guards, so the symbols
were defined twice in src/main.cpp.

Fix:
Removed the duplicate individual GFXFF #include directives from include/Theme.h.
The firmware still uses exactly the same FreeSans / FreeSansBold font objects;
they now come from TFT_eSPI's normal LOAD_GFXFF path.

Recommended clean rebuild after replacing/extracting the project:
  pio run -t clean
  pio run
  pio run -t upload

If VS Code still shows stale diagnostics, delete .pio once or use PlatformIO:
Project Tasks > General > Clean.
